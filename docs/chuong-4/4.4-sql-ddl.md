# Mục 4.4 – DDL: Tạo và Quản Lý Cấu Trúc Bảng

---

## 🔹 1. GIỚI THIỆU SIÊU CƠ BẢN

### DDL là gì?

Trước khi nhập dữ liệu vào CSDL, bạn phải **tạo ra cấu trúc** để chứa dữ liệu — giống như trước khi đổ xi măng, bạn phải **đóng ván khuôn** trước.

**DDL (Data Definition Language – Ngôn ngữ định nghĩa dữ liệu)** là nhóm câu lệnh SQL dùng để **tạo, sửa và xóa cấu trúc** của CSDL (bảng, cột, ràng buộc...).

Ba lệnh DDL cốt lõi:
- **`CREATE TABLE`** – Tạo bảng mới
- **`ALTER TABLE`** – Chỉnh sửa cấu trúc bảng đã có
- **`DROP TABLE`** – Xóa toàn bộ bảng (kể cả dữ liệu bên trong)

> 💡 **Ghi nhớ:** DDL thay đổi *cấu trúc* của CSDL, không phải *dữ liệu* bên trong. Sau mỗi lệnh DDL, thay đổi được áp dụng ngay lập tức và **không thể rollback** trong đa số DBMS.

## 🔹 2. LÝ THUYẾT CHI TIẾT

### 2.1 CREATE TABLE – Tạo bảng mới

> **Định nghĩa:** `CREATE TABLE` dùng để tạo một bảng mới trong CSDL với các cột và ràng buộc được chỉ định.

**Cú pháp:**
```sql
CREATE TABLE ten_bang (
    ten_cot1  kieu_du_lieu  [rang_buoc],
    ten_cot2  kieu_du_lieu  [rang_buoc],
    ...
    [CONSTRAINT rang_buoc_bang]
);
```

**Các kiểu dữ liệu thường gặp:**
| Kiểu | Ý nghĩa | Ví dụ |
|---|---|---|
| `INT` | Số nguyên | Tuổi, số lượng |
| `DECIMAL(p, s)` | Số thập phân | `DECIMAL(5,2)` = tối đa 999.99 |
| `VARCHAR(n)` | Chuỗi ký tự có độ dài tối đa n | Tên, địa chỉ |
| `CHAR(n)` | Chuỗi cố định n ký tự | Mã bưu chính |
| `DATE` | Ngày tháng năm | `2024-05-10` |
| `DATETIME` | Ngày và giờ | `2024-05-10 08:30:00` |
| `BOOLEAN` | Đúng/Sai | `TRUE` / `FALSE` |
| `TEXT` | Chuỗi rất dài | Nội dung bài viết |

**Các ràng buộc (constraint) thường dùng:**
| Ràng buộc | Ý nghĩa |
|---|---|
| `PRIMARY KEY` | Khóa chính: duy nhất, không NULL |
| `NOT NULL` | Bắt buộc phải có giá trị |
| `UNIQUE` | Giá trị duy nhất (cho phép NULL) |
| `DEFAULT gia_tri` | Giá trị mặc định khi không nhập |
| `CHECK (dieu_kien)` | Kiểm tra điều kiện hợp lệ |
| `FOREIGN KEY` | Khóa ngoại tham chiếu bảng khác |
| `AUTO_INCREMENT` | Tự động tăng (dùng cho số ID) |

---

### 2.2 ALTER TABLE – Sửa cấu trúc bảng

> **Định nghĩa:** `ALTER TABLE` dùng để **thay đổi cấu trúc** của bảng đã tồn tại: thêm cột, xóa cột, đổi tên cột, thay đổi kiểu dữ liệu, thêm/xóa ràng buộc.

**Các thao tác với ALTER TABLE:**
```sql
-- Thêm cột mới
ALTER TABLE ten_bang ADD ten_cot kieu_du_lieu [rang_buoc];

-- Xóa cột
ALTER TABLE ten_bang DROP COLUMN ten_cot;

-- Đổi kiểu dữ liệu của cột (MySQL)
ALTER TABLE ten_bang MODIFY COLUMN ten_cot kieu_moi;

-- Đổi tên cột (MySQL 8+)
ALTER TABLE ten_bang RENAME COLUMN ten_cu TO ten_moi;

-- Thêm ràng buộc
ALTER TABLE ten_bang ADD CONSTRAINT ten_rc FOREIGN KEY (cot) REFERENCES bang_khac(cot);

-- Xóa ràng buộc
ALTER TABLE ten_bang DROP CONSTRAINT ten_rc;
```

---

### 2.3 DROP TABLE – Xóa bảng

> **Định nghĩa:** `DROP TABLE` xóa hoàn toàn một bảng khỏi CSDL, bao gồm cả **toàn bộ dữ liệu** và **cấu trúc** của bảng đó.

```sql
DROP TABLE ten_bang;

-- Xóa nếu tồn tại (tránh lỗi khi bảng chưa có)
DROP TABLE IF EXISTS ten_bang;
```

> ⚠️ **Cảnh báo:** `DROP TABLE` **không thể hoàn tác**. Toàn bộ dữ liệu trong bảng sẽ mất vĩnh viễn. Hãy backup trước khi dùng lệnh này.

**Lệnh liên quan – TRUNCATE TABLE:** Xóa toàn bộ *dữ liệu* nhưng giữ lại *cấu trúc* bảng:
```sql
TRUNCATE TABLE ten_bang;
```

## 🔹 3. GIẢI THÍCH BẢN CHẤT

### Hình dung DDL qua ví dụ thực tế

Hãy nghĩ đến việc xây dựng một **bảng theo dõi đơn hàng** trong cửa hàng:

- **`CREATE TABLE`** = Đặt mua tủ hồ sơ mới, chia ngăn kéo và dán nhãn: "Tên khách", "Ngày đặt", "Số tiền"...
- **`ALTER TABLE`** = Đập thêm ngăn kéo mới vào tủ đang dùng (ví dụ: thêm cột "Địa chỉ giao hàng" vì trước đó quên)
- **`DROP TABLE`** = Đem cả tủ hồ sơ ra đốt — mọi thứ bên trong biến mất

> 💡 **Thứ tự tạo bảng quan trọng:** Phải tạo bảng **cha** (bảng được tham chiếu bởi FK) trước bảng **con**. Ví dụ: tạo `Lop` trước, rồi mới tạo `HocSinh` (vì `HocSinh` có FK trỏ về `Lop`).

## 🔹 4. LUỒNG HOẠT ĐỘNG STEP-BY-STEP

**Tình huống:** Xây dựng CSDL quản lý thư viện từ đầu

**Bước 1 – Phân tích:** Xác định cần những bảng nào, mỗi bảng có cột gì, kiểu dữ liệu và ràng buộc ra sao.

**Bước 2 – Tạo bảng cha trước:**
```sql
CREATE TABLE DocGia (MaDG VARCHAR(10) PRIMARY KEY, ...);
CREATE TABLE Sach   (MaSach VARCHAR(10) PRIMARY KEY, ...);
```

**Bước 3 – Tạo bảng con (có FK) sau:**
```sql
CREATE TABLE MuonSach (
    MaDG   VARCHAR(10),
    MaSach VARCHAR(10),
    FOREIGN KEY (MaDG) REFERENCES DocGia(MaDG),
    FOREIGN KEY (MaSach) REFERENCES Sach(MaSach)
);
```

**Bước 4 – Kiểm tra và chỉnh sửa nếu cần:**
```sql
ALTER TABLE Sach ADD TheLoai VARCHAR(50);  -- quên thêm cột TheLoai
```

**Bước 5 – Khi không cần bảng nữa:**
```sql
DROP TABLE IF EXISTS MuonSach;  -- xóa bảng con trước
DROP TABLE IF EXISTS Sach;
DROP TABLE IF EXISTS DocGia;
```

## 🔹 5. VÍ DỤ MINH HỌA

### Chuẩn bị: Dữ liệu mẫu dùng chung cho các ví dụ

> Tất cả ví dụ trong mục này đều xây dựng hệ thống quản lý trường học gồm 4 bảng: `Lop`, `HocSinh`, `MonHoc`, `DiemThi`.

---

### Ví dụ 1 – Cơ bản: Tạo bảng đơn giản

**Yêu cầu:** Tạo bảng `Lop` để lưu thông tin các lớp học.

```sql
CREATE TABLE Lop (
    MaLop   VARCHAR(10)  PRIMARY KEY,   -- Mã lớp, duy nhất, không rỗng
    TenLop  VARCHAR(50)  NOT NULL,       -- Tên lớp, bắt buộc phải có
    KhoiLop INT          NOT NULL,       -- Khối lớp (10, 11, hoặc 12)
    SiSo    INT          DEFAULT 0       -- Sĩ số, mặc định là 0 nếu không nhập
);
```

**Giải thích từng dòng:**
- `MaLop VARCHAR(10) PRIMARY KEY` — chuỗi tối đa 10 ký tự, vừa là khóa chính
- `TenLop VARCHAR(50) NOT NULL` — bắt buộc phải nhập, không để trống
- `KhoiLop INT NOT NULL` — số nguyên, bắt buộc
- `SiSo INT DEFAULT 0` — nếu khi thêm dòng không nhập `SiSo`, tự động điền `0`

**Kiểm tra bảng vừa tạo (MySQL):**
```sql
DESCRIBE Lop;
-- hoặc
SHOW COLUMNS FROM Lop;
```

---

### Ví dụ 2 – Thực tế: Tạo bảng có ràng buộc đầy đủ

**Yêu cầu:** Tạo bảng `HocSinh` với đầy đủ ràng buộc liên kết đến bảng `Lop`.

```sql
CREATE TABLE HocSinh (
    MaHS     VARCHAR(10)   PRIMARY KEY,
    HoTen    VARCHAR(100)  NOT NULL,
    NgaySinh DATE,
    GioiTinh VARCHAR(3)    CHECK (GioiTinh IN ('Nam', 'Nữ')),
    DiemTB   DECIMAL(4,2)  DEFAULT 0.00,
    MaLop    VARCHAR(10),
    FOREIGN KEY (MaLop) REFERENCES Lop(MaLop)
);
```

**Giải thích các ràng buộc:**
- `CHECK (GioiTinh IN ('Nam', 'Nữ'))` — DBMS tự từ chối nếu nhập giá trị khác 'Nam' hoặc 'Nữ'
- `DECIMAL(4,2)` — tối đa 4 chữ số, trong đó 2 chữ số sau dấu phẩy (vd: `10.00`, `9.75`)
- `FOREIGN KEY (MaLop) REFERENCES Lop(MaLop)` — `MaLop` trong `HocSinh` phải tồn tại trong bảng `Lop`

---

### Ví dụ 3 – Nâng cao: Dùng ALTER TABLE để cập nhật cấu trúc

**Tình huống:** Sau khi tạo bảng `HocSinh`, nhà trường muốn thêm thông tin số điện thoại phụ huynh và xóa cột `DiemTB` (vì điểm trung bình tính từ bảng `DiemThi`).

```sql
-- Bước 1: Thêm cột SdtPhuHuynh
ALTER TABLE HocSinh
    ADD SdtPhuHuynh VARCHAR(15);

-- Bước 2: Xóa cột DiemTB vì không cần nữa
ALTER TABLE HocSinh
    DROP COLUMN DiemTB;

-- Bước 3: Đổi độ dài cột HoTen từ 100 lên 150 ký tự
ALTER TABLE HocSinh
    MODIFY COLUMN HoTen VARCHAR(150) NOT NULL;
```

**Kết quả:** Cấu trúc bảng `HocSinh` sau khi ALTER:
```
MaHS        VARCHAR(10)   PRIMARY KEY
HoTen       VARCHAR(150)  NOT NULL
NgaySinh    DATE
GioiTinh    VARCHAR(3)
SdtPhuHuynh VARCHAR(15)          ← mới thêm
MaLop       VARCHAR(10)   FK→Lop
```

## 🔹 6. SO SÁNH & PHÂN BIỆT

### CREATE TABLE vs. ALTER TABLE vs. DROP TABLE

| | `CREATE TABLE` | `ALTER TABLE` | `DROP TABLE` |
|---|---|---|---|
| Mục đích | Tạo bảng mới | Sửa cấu trúc bảng có sẵn | Xóa hoàn toàn bảng |
| Khi dùng | Lần đầu xây dựng CSDL | Thêm/sửa/xóa cột sau khi đã có dữ liệu | Khi bảng không cần nữa |
| Ảnh hưởng dữ liệu | Không (bảng rỗng) | Có thể ảnh hưởng nếu xóa cột có dữ liệu | Xóa toàn bộ dữ liệu |
| Nguy hiểm | Ít | Trung bình | Rất nguy hiểm |

### DROP TABLE vs. TRUNCATE TABLE vs. DELETE

| | `DROP TABLE` | `TRUNCATE TABLE` | `DELETE` |
|---|---|---|---|
| Xóa cấu trúc | ✅ Có | ❌ Không | ❌ Không |
| Xóa dữ liệu | ✅ Tất cả | ✅ Tất cả | ✅ Theo điều kiện |
| Có thể rollback | ❌ Không | ❌ Không | ✅ Có |
| Tốc độ | Nhanh nhất | Nhanh | Chậm hơn với dữ liệu lớn |
| Thuộc nhóm | DDL | DDL | DML |

## 🔹 7. GHI NHỚ NHANH (ĐI THI)

- 📌 **DDL** = nhóm lệnh thay đổi *cấu trúc* CSDL (không phải dữ liệu)
- 📌 **CREATE TABLE** = tạo bảng mới với cột và ràng buộc
- 📌 **ALTER TABLE** = thêm/sửa/xóa cột hoặc ràng buộc của bảng có sẵn
- 📌 **DROP TABLE** = xóa toàn bộ bảng (mất hết dữ liệu, không hoàn tác được)
- 📌 **TRUNCATE TABLE** = xóa hết dữ liệu, giữ lại cấu trúc bảng
- 📌 Các kiểu dữ liệu quan trọng: `INT`, `VARCHAR(n)`, `DECIMAL(p,s)`, `DATE`, `BOOLEAN`
- 📌 Các ràng buộc quan trọng: `PRIMARY KEY`, `NOT NULL`, `UNIQUE`, `DEFAULT`, `CHECK`, `FOREIGN KEY`
- 📌 Tạo bảng **cha trước, con sau** khi có khóa ngoại

## 🔹 8. BÀI TẬP TỰ LUYỆN

**Câu 1 (Dễ):** Viết lệnh SQL tạo bảng `MonHoc` với các cột: `MaMon` (VARCHAR(10), khóa chính), `TenMon` (VARCHAR(100), không rỗng), `SoTietHoc` (INT, mặc định là 45).

> **Đáp án:**
> ```sql
> CREATE TABLE MonHoc (
>     MaMon     VARCHAR(10)  PRIMARY KEY,
>     TenMon    VARCHAR(100) NOT NULL,
>     SoTietHoc INT          DEFAULT 45
> );
> ```

---

**Câu 2 (Dễ):** Viết lệnh SQL để thêm cột `PhongHoc` (VARCHAR(20)) vào bảng `Lop` đã có sẵn.

> **Đáp án:**
> ```sql
> ALTER TABLE Lop
>     ADD PhongHoc VARCHAR(20);
> ```

---

**Câu 3 (Trung bình):** Viết lệnh SQL tạo bảng `DiemThi` với: `MaHS` (VARCHAR(10)), `MaMon` (VARCHAR(10)), `Diem` (DECIMAL(4,2)), `NgayThi` (DATE). Trong đó `(MaHS, MaMon)` là khóa chính phức, `MaHS` tham chiếu bảng `HocSinh`, `MaMon` tham chiếu bảng `MonHoc`.

> **Đáp án:**
> ```sql
> CREATE TABLE DiemThi (
>     MaHS    VARCHAR(10),
>     MaMon   VARCHAR(10),
>     Diem    DECIMAL(4,2),
>     NgayThi DATE,
>     PRIMARY KEY (MaHS, MaMon),
>     FOREIGN KEY (MaHS)  REFERENCES HocSinh(MaHS),
>     FOREIGN KEY (MaMon) REFERENCES MonHoc(MaMon)
> );
> ```

---

**Câu 4 (Trung bình):** Viết lệnh SQL để xóa cột `PhongHoc` vừa thêm vào bảng `Lop` ở câu 2.

> **Đáp án:**
> ```sql
> ALTER TABLE Lop
>     DROP COLUMN PhongHoc;
> ```

---

**Câu 5 (Vận dụng):** Cần xóa toàn bộ hệ thống CSDL trường học gồm 4 bảng: `DiemThi`, `HocSinh`, `MonHoc`, `Lop`. Viết các lệnh SQL theo đúng thứ tự để tránh lỗi vi phạm khóa ngoại.

> **Đáp án:** Phải xóa bảng *con* (có FK) trước bảng *cha*:
> ```sql
> DROP TABLE IF EXISTS DiemThi;  -- có FK → HocSinh và MonHoc
> DROP TABLE IF EXISTS HocSinh;  -- có FK → Lop
> DROP TABLE IF EXISTS MonHoc;
> DROP TABLE IF EXISTS Lop;
> ```

## 🔹 9. LỖI THƯỜNG GẶP

| Lỗi | Ví dụ sai | Cách sửa |
|---|---|---|
| Tạo bảng con trước bảng cha | Tạo `HocSinh` (có FK→Lop) trước khi tạo `Lop` | Tạo `Lop` trước, rồi mới tạo `HocSinh` |
| Xóa bảng cha khi còn bảng con tham chiếu | `DROP TABLE Lop` khi `HocSinh` còn FK→Lop | Xóa `HocSinh` trước, rồi mới `DROP TABLE Lop` |
| Quên NOT NULL cho cột quan trọng | `HoTen VARCHAR(100)` — cho phép lưu học sinh không có tên | Thêm `NOT NULL`: `HoTen VARCHAR(100) NOT NULL` |
| Nhầm TRUNCATE và DROP | Dùng `DROP TABLE` khi chỉ muốn xóa dữ liệu | Dùng `TRUNCATE TABLE` để giữ cấu trúc |
| Dùng AUTO_INCREMENT sai vị trí | `MaHS AUTO_INCREMENT VARCHAR(10)` — sai cú pháp | `AUTO_INCREMENT` viết sau kiểu dữ liệu: `MaHS INT AUTO_INCREMENT PRIMARY KEY` |
| Quên kiểm tra bảng có tồn tại trước khi DROP | `DROP TABLE Lop` khi bảng chưa tồn tại → lỗi | Dùng `DROP TABLE IF EXISTS Lop` để an toàn |
